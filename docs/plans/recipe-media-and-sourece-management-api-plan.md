# API Plan - Recipe Media and Source Management

## Overview

This feature enables users to attach up to two images (thumbnails/full-size) and a source URL to recipes. It transitions
the recipe creation process to support multipart uploads, introduces secure S3-based storage with presigned URLs, and
manages media metadata within the existing JSONB structure.

## API Endpoints

### Create Recipe

* **Path**: `POST /recipes`
* **Purpose**: Creates a new recipe with optional initial images and source URL.
* **Authentication**: User (OWNER context)
* **Request Parameters**:
    - **Content-Type**: `multipart/form-data`
    - **Body Parts**:
        - `data`: `application/json` (Recipe creation metadata including `sourceUrl`)
        - `images`: `image/jpeg` or `image/png` (Array of binary files, max 2, max 5MB each)
* **Response**:
    - **Success (201)**: Returns `RecipeDto` including generated `imageIds` and presigned URLs.
    - **Error (400)**: Invalid file type, file size exceeded, or invalid JSON.
* **Notes**: Atomic transaction. If S3 upload fails, DB record is rolled back. Backend generates thumbnails for all
  uploads.

### Add or Replace Image

* **Path**: `POST /recipes/{recipeId}/images`
* **Purpose**: Uploads a single image to an existing recipe, either adding a new one or replacing an existing one.
* **Authentication**: User (OWNER or EDITOR)
* **Request Parameters**:
    - **Path**: `recipeId` (UUID)
    - **Query**: `replaceImageId` (UUID, Optional) - If provided, replaces this specific image ID.
    - **Content-Type**: `multipart/form-data`
    - **Body Parts**:
        - `image`: `image/jpeg` or `image/png` (Binary file)
* **Response**:
    - **Success (204)**: No Content.
    - **Error (400)**: limit reached (if adding > 2), file size/type errors.
    - **Error (404)**: Recipe or `replaceImageId` not found.
* **Notes**: Automatically updates the `imageIds` list in the JSONB column.

### Update Recipe Details

* **Path**: `PUT /recipes/{recipeId}`
* **Purpose**: Updates recipe metadata, including `sourceUrl` and the order of images.
* **Authentication**: User (OWNER or EDITOR)
* **Request Parameters**:
    - **Path**: `recipeId` (UUID)
    - **Body**: `UpdateRecipeRequest` (JSON)
      ```json
      {
        "name": "...",
        "data": {
          "sourceUrl": "https://new-source.com",
          "imageIds": ["uuid-2", "uuid-1"] // Reordering or removing IDs
        }
      }
      ```
* **Response**:
    - **Success (200)**: Returns updated `RecipeDto`.
* **Notes**:
    - If an ID present in the DB is missing from the request `imageIds`, the backend marks the file for asynchronous
      deletion from S3.
    - The first ID in `imageIds` determines the thumbnail used in list views.

### Get Recipe Details

* **Path**: `GET /recipes/{recipeId}`
* **Purpose**: Retrieves full recipe details including secure, time-limited download URLs for media.
* **Authentication**: User (OWNER, EDITOR, or Viewer)
* **Request Parameters**:
    - **Path**: `recipeId` (UUID)
* **Response**:
    - **Success (200)**: `RecipeDto`
      ```json
      {
        "id": "...",
        "sourceUrl": "https://...",
        "images": [
          {
            "id": "uuid-1",
            "url": "https://s3.aws... (presigned)",
            "thumbnailUrl": "https://s3.aws... (presigned)"
          }
        ]
      }
      ```

### List Recipes

* **Path**: `GET /recipes`
* **Purpose**: Lists recipes with a thumbnail for visual identification.
* **Authentication**: User
* **Request Parameters**:
    - **Query**: Standard pagination/filtering params.
* **Response**:
    - **Success (200)**: List of `RecipeListDto`
      ```json
      [
        {
          "id": "...",
          "name": "...",
          "thumbnailUrl": "https://s3.aws... (presigned for uuid-1)"
        }
      ]
      ```

## Data Models

### Recipe JSONB Data Extension

*Extends the existing `data` column in `recipes` table.*

```json
{
  "description": "string | optional",
  "ingredients": [],
  "steps": [],
  "sourceUrl": "string | URL format, optional",
  "imageIds": "List<UUID> | ordered list of image identifiers"
}
```

* **Validation Rules**:
    - `sourceUrl`: Must be a valid HTTP/HTTPS URL.
    - `imageIds`: Max 2 entries. IDs must be valid UUIDs.

### RecipeImageDto

*Used in API responses, not persisted directly.*

```json
{
  "id": "UUID | The image identifier",
  "url": "String | Presigned S3 URL for full-size image",
  "thumbnailUrl": "String | Presigned S3 URL for thumbnail"
}
```

## Integration Points

* **PostgreSQL**:
    - **Table**: `recipes`
    - **Column**: `data` (JSONB) - Updated to store `sourceUrl` and `imageIds`.
* **AWS S3 (Object Storage)**:
    - **Bucket**: Private.
    - **Key Pattern**: `recipes/{recipe_id}/{image_id}.jpg` and `recipes/{recipe_id}/{image_id}-thumb.jpg`.
    - **Access**: Via Presigned URLs generated by the backend.
* **Spring Application Events**:
    - Used to trigger asynchronous S3 cleanup tasks when images are removed via PUT or DELETE operations.
